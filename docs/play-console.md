# Play Console の申告

## 概要

Google Play Console に入れる答えと、その入れ方。Play Console の答えは、ここを元にする。

| 文書 | 受け持つこと |
|---|---|
| 本書 | Play Console のどこに何を入れるか（[手順](#手順)）と、入れる答え（[登録するデータのまとめ](#登録するデータのまとめ)） |
| [privacy-policy.md](privacy-policy.md) | プライバシーポリシー。アプリが送る情報・権限を変えたら、本書の[データ セーフティ](#データ-セーフティ)と合わせて直す |
| [release.md](release.md) | 版を上げて AAB を作り、トラックに出す流れ |
| [play-api.md](play-api.md) | `tools/play.mjs` で API から出すしくみ・準備・使い方 |

Play Console で入れるのは、主に次の 3 か所。アプリを選んでから、左のメニューで開く。メニューの名前が変わって見つからないときは、上の検索欄で項目名を探す。

| 場所 | 入れるもの |
|---|---|
| **[ポリシーとプログラム] > [アプリのコンテンツ]** | データ セーフティ・アプリのアクセス権・広告・コンテンツのレーティング・対象年齢・フォアグラウンドサービスなど。それぞれの **[管理]** から入れる |
| **[ユーザーを増やす] > [ストアの掲載情報]** | アプリ名・説明文・アイコン・スクリーンショットなど |
| **[公開の概要]** | 保存した変更を審査に出す |

API（`tools/play.mjs`、[play-api.md](play-api.md)）でも送れるのは、AAB のアップロード、ストアの説明文、データ セーフティ（Play Console の書き出しと同じ形式の CSV）、審査への送信。アプリのアクセス権など、ほかのアプリのコンテンツは画面で入れる。

## 手順

### 初回の登録

1. アプリを作り、[アプリの基本](#アプリの基本)の表のとおりに、価格・公開する国・カテゴリ・連絡先の詳細などを入れる
2. [アプリのコンテンツ] を、[アプリの基本](#アプリの基本)・[データ セーフティ](#データ-セーフティ)・[フォアグラウンドサービスの申告](#フォアグラウンドサービスの申告)の答えで埋める。フォアグラウンドサービスの申告には動画を撮る
3. [ストアの掲載情報](#ストアの掲載情報)を入れる
4. 内部テストに AAB を上げ（[release.md](release.md)）、[審査に出す](#審査に出す)
5. 個人のデベロッパー アカウントは、本番の前に 12 人以上・14 日以上のクローズドテストをする

### 送る情報を変えたとき

1. [privacy-policy.md](privacy-policy.md) を直してマージする（GitHub Pages に出る）。アプリの更新より先に公開する
2. 本書の[データ セーフティ](#データ-セーフティ)を直し、Play Console に入れる。ストアの説明文に書いてあることなら、[詳しい説明](#詳しい説明)と [Pages のトップ](index.html) も直す
3. 新しい版と同じ審査に出す。別々に出すと、申告とアプリの動きが食い違う期間ができる

### データ セーフティの入れ方

[アプリのコンテンツ] の「データ セーフティ」の **[管理]** から開き、次のページを **[次へ]** で進んで、最後に **[保存]** する。

| ページ | 入れるもの |
|---|---|
| 概要 | なし |
| データの収集とセキュリティ | [データ セーフティ](#データ-セーフティ)の最初の表の質問（アカウントとデータの削除を含む） |
| データの種類 | [収集するデータ](#収集するデータ)の表の種類にチェックを入れる |
| データの使用と処理 | チェックした種類ごとに **[開始]** を押し、表の「収集」「共有」「一時的な処理」「任意か」「目的」を答える。目的の「不正行為の防止・セキュリティ」は、選択肢の「不正行為の防止、セキュリティ、コンプライアンス」 |
| プレビュー | ストアに出る形を確かめる |

同じ画面の「CSV にエクスポート」で、入れた答えを書き出せる。「CSV をインポート」と `tools/play.mjs data-safety` は、この形式の CSV で答えを置き換える。答えを入れた CSV は [play-data-safety.csv](play-data-safety.csv)（Play Console の書き出しの形式のまま、改行は CRLF）。本書の答えを変えたら、この CSV も直す。

### 審査に出す

アプリのコンテンツ・ストアの掲載情報の変更と、新しいリリースは、保存しただけでは公開されない。

1. 新しい版を出すときは、トラック（**[テストとリリース] > [テスト] > [内部テスト]** など）の **[新しいリリースを作成]** で AAB を上げ、リリースノートを書いて保存する
2. 左のメニューの **[公開の概要]** を開く。審査に出していない変更が並ぶ
3. **[変更を審査に送信]** を押す

API では、`tools/play.mjs edit … --commit` が 1〜3 にあたる。Play Console で保存して審査に出していない変更も一緒に出る。

カテゴリ・タグ・連絡先の詳細は[アプリの基本](#アプリの基本)の表のとおり。言語は日本語だけ（英語の掲載情報は、アプリが英語に対応してから足す）。「AI で翻訳をインポート」は使わない。カスタムのストアの掲載情報は作らない。AI アセットの申告は「使った」（アイコン・フィーチャー グラフィック・説明文は生成 AI で作った。スクリーンショットはアプリの実際の画面）。

| スマートフォンのスクリーンショット | 2〜8 枚、辺は 320〜3840px、縦横比 2:1 まで、JPEG か 24 ビット PNG | [下の 5 枚](#スクリーンショット) |
| タブレット・Chromebook・Android XR のスクリーンショット | 任意 | 出さない（スマートフォン向け） |
| 動画 | 任意（YouTube の URL） | 出さない |

説明文には、星・絵文字・「No.1」などの誇張を使わない。運営の AI には 1 日の回数の上限があること、自分の API キーを使うときはその利用料が各サービスから散策者に請求されることは必ず書く。位置を外部に送ることは[データ セーフティ](#データ-セーフティ)の申告と合わせる。機能・送る情報・対応する AI サービスを変えたら、説明文と [Pages のトップ](index.html) を合わせて直す。

`tools/play.mjs` の `--listing` は、下の 2 つの見出しのすぐ下の `text` のコードブロックを送る。

#### 簡単な説明

```text
歩きながら周りのスポットを案内し、天気や休憩に合わせて声で話しかける散策のお供
```

#### 詳しい説明

```text
散策ガイドは、一緒に歩きながら周りのスポットを案内し、その時々の状況に合わせて話しかける散策のお供です。

■ スポットの案内
現在地の周りの史跡・寺社・公園・博物館などを地図と一覧に出します。スポットを選ぶと、AI がガイドのように解説し、読み上げます。写真が登録されているスポットでは、作者とライセンスとともに写真も表示します。

■ 散策モード
散策を始めると、歩いている間に音声で話しかけます。
・スポットに近づいたとき（前に訪れた場所なら、前回を踏まえた短い一言）
・しばらく休憩したとき
・1 時間以内に雨や雷雨になりそうなとき
・日の入りが近づいたとき
・散策の始まりと終わり

■ 散策に役立つ施設
トイレ・水飲み場・自動販売機・休憩所・ベンチを地図に出します。歩いた時間や気温、天気に合わせて、必要そうなときに近くの施設を知らせます。

■ チャンネル
標準・歴史探訪・自然観察・グルメの旅・ショッピング・しずかに から、語り手と話題を選べます。

■ 散策前のプラン
テーマ・時間・距離を選び、近くの立ち寄り先を決めてから歩けます。

■ 散歩の記録
日時・距離・経路・案内したスポットを端末の中に残し、あとから振り返れます。

■ 使うときに必要なもの
・位置情報の許可
・AI の解説と話しかけは、設定なしで「運営の AI」を使えます。1 日に使える回数に上限があり、使い切った日は決まった文で案内します。
・生成AI サービス（Anthropic・OpenAI・Google・DeepSeek、または OpenAI 互換のサービス）の API キーを持っていれば、設定の画面で切り替えて使えます。API キーの利用料は、各サービスから散策者に請求されます。

■ プライバシー
アカウントの登録、利用状況の解析、広告はありません。散歩の記録と API キーは端末の中だけに保存します。運営の AI を使うときは、解説と話しかけに使う情報が運営の中継を通りますが、中継は内容を保存しません。位置は、スポットや天気を調べるために外部のサービスへ送ります。AI には、既定では緯度経度と歩いた経路を送りません。詳しくはプライバシーポリシーをご覧ください。

地図データ © OpenStreetMap の貢献者
```

#### スクリーンショット

[`store/screenshots/`](../store/screenshots/) の 5 枚を、番号の順に入れる。どれも散策中で、エラーの出ていない画面。

1. `01-walking.png`: 歴史探訪のチャンネルで、近づいたスポットを案内し、そこまでのルートを地図に描いたところ
2. `02-spot-detail.png`: 「解説を読む」で開いた、スポットの AI 解説と Wikimedia Commons の写真
3. `03-spot-card.png`: 一覧で選んだスポットを地図で強調し、カードの「解説を聞く」「解説を読む」とルートを出したところ
4. `04-channels.png`: チャンネルを選ぶところ
5. `05-greeting.png`: 散策を始めたときのあいさつ

撮り方:

- エミュレータの画面を 1080×2160（`adb shell wm size 1080x2160`。縦横比を 2:1 に収める）にし、端末の時刻帯を `Asia/Tokyo` にして、昼の配色で撮る
- 位置は観光地（浅草寺の周り）にし、`adb emu geo fix` で少しずつ動かして歩いた状態にする。API キーと自宅の周りの位置は写さない
- ステータスバーはデモ モード（`com.android.systemui.demo`）で時計・電池・電波をそろえる
- スポットの検索が Overpass のエラーで失敗したら、再検索してから撮る
- 散歩の記録の画面は、試しの散歩の一覧しか出ないので入れない
- 撮った PNG は透過を外して 24 ビットにする（`magick 画像 -background white -alpha remove -alpha off PNG24:画像`）

アイコンとフィーチャー グラフィックは [`store/src/`](../store/src/) の SVG から `sh store/src/build.sh` で作る。Play に出す画像と動画（アイコン・フィーチャー グラフィック・スクリーンショット・[フォアグラウンドサービスの申告](#フォアグラウンドサービスの申告)の動画）は、すべて [`store/`](../store/) に置く。

### データ セーフティ

Google の定義では、端末から外に送るものは、送り先が運営者のサーバーでなくても「収集」になる（例外は、端末の中だけで処理するものと、エンドツーエンドで暗号化するものだけ。HTTPS は当たらない）。スポット・経路・天気を調べるには位置を外に送るので、「収集」は「いいえ」にできない。外部サービスに送る位置などと、運営の AI の中継に送るものを「収集」として申告する。入れ方は[データ セーフティの入れ方](#データ-セーフティの入れ方)。

| 質問 | 答え |
|---|---|
| 対象になる種類のユーザーデータを収集または共有するか | はい |
| 送るデータはすべて転送時に暗号化されるか | はい（通信はすべて HTTPS） |
| アプリが対応しているアカウントの作成方法 | なし（ログインなし） |
| アプリ外で作成したアカウントでログインできるか | いいえ（API キーは AI サービスに送る鍵で、本アプリへのログインではない） |
| データの削除をリクエストできるか | 「いいえ（ただしユーザーデータは 90 日以内に自動で削除）」。運営が持つのは中継の回数の記録だけで、7 日で消える。端末のデータはアプリの中で消せる（記録の画面・アプリの削除）。「はい」にするとデータ削除用の URL が必須になる |

#### 収集するデータ

| データの種類 | 収集 | 共有 | 一時的な処理 | 任意か | 目的 |
|---|---|---|---|---|---|
| 位置情報 > おおよその位置情報 | はい | いいえ | はい | 必須 | アプリの機能 |
| 位置情報 > 正確な位置情報 | はい | いいえ | はい | 必須 | アプリの機能 |
| アプリのアクティビティ > その他のユーザー作成コンテンツ（散策の状況のまとめを AI へ） | はい | いいえ | はい | 任意（AI を使うときだけ） | アプリの機能 |
| デバイスまたはその他の ID（運営の AI の中継へのインストール ID） | はい | いいえ | いいえ | 任意（運営の AI を使うときだけ） | アプリの機能、不正行為の防止・セキュリティ |

- **共有はいいえ**: Overpass・OSRM・Open-Meteo・AI サービスなどへの送信は、散策者が求めた機能を提供するためのもので、送り先は位置を別の目的に使う相手として渡していない。運営の AI では、中継が Amazon Bedrock に渡すだけで、Bedrock は内容を別の目的に使わない。自分の API キーでは、散策者が選んだサービスに送る
- **一時的な処理**: 位置と散策の状況は、運営者も保管しない（中継は内容を保存しない）。各サービスでの扱いは、それぞれのポリシーに従う（プライバシーポリシーの「外部サービスへの送信」）。インストール ID は、中継が回数を数えるために HMAC にして 7 日保管するので「いいえ」
- **申告しないもの**: 散歩の記録・設定・API キーは端末の外に出ない（バックアップ・端末間の移行もしない）。個人情報（名前・メールアドレス）、端末そのものの ID（Android ID・広告 ID）、アプリの診断情報は扱わない

### フォアグラウンドサービスの申告

| 項目 | 答え |
|---|---|
| 種類 | 位置情報（`foregroundServiceType="location"`、`FOREGROUND_SERVICE_LOCATION`） |
| バックグラウンドの位置情報の権限 | 求めない（`ACCESS_BACKGROUND_LOCATION` なし。散策者が画面で「散策をはじめる」を押したときに始める） |
| 説明 | 散策者が「散策をはじめる」を押してから「散策を終える」を押すまで、画面を閉じても現在地を追い、近づいたスポットの解説と、歩いた距離・経路の記録をする。散策中は通知を出し続け、通知の「終了」からも終えられる |
| 散策者への影響 | 位置を追うのをやめると、画面を閉じている間のスポットの案内と、散歩の記録が途切れる |
| 動画 | [`store/videos/foreground-service-demo.mp4`](../store/videos/foreground-service-demo.mp4)。「散策をはじめる」→ 通知が出る → 画面を閉じる → スポットに近づくと案内が出る → 「散策を終える」の流れ。URL は jsDelivr から配信したもの https://cdn.jsdelivr.net/gh/duwenji/yorisoi-sanpoguide@fa274fd/store/videos/foreground-service-demo.mp4 を入れる（`video/mp4` で返るので、ブラウザでそのまま再生できる。GitHub のファイルのページは再生せず、ダウンロードになる）。`@` の後ろは動画を入れたコミット。`@main` にすると CDN に最大 7 日古い版が残るので、コミットで固定する。撮り直したら同じファイル名で置き換え、その後のコミットに URL を直して Play Console で入れ直す |
