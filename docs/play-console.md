# Play Console の申告

Google Play Console の「アプリのコンテンツ」に入れる答え。アプリが送る情報・権限を変えたら、ここと [privacy-policy.md](privacy-policy.md) を合わせて直す。

## アプリを作成して内部テストする

各テスト方法の目的と推奨する実施順は、[アプリの公開と更新 > テスト方法と進め方](release.md#テスト方法と進め方)を参照する。

### 「アプリを作成」画面

Play Console のホームから **[アプリを作成]** を選び、次の値を入れる。

| 項目                                   | 入力値                                   | 注意                                                                                                       |
| -------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| アプリ名                               | `散策ガイド`                           | アプリの表示名。後から変更できる                                                                           |
| パッケージ名                           | `io.github.duwenji.yorisoi.sanpoguide` | `app/build.gradle.kts` の `applicationId` と完全に一致させる。利用可能か確認し、別の値に変えない       |
| デフォルトの言語                       | 日本語（日本） - `ja-JP`               | ストア掲載情報の既定言語                                                                                   |
| アプリ / ゲーム                        | アプリ                                   | 散策ガイドはゲームではない                                                                                 |
| 無料 / 有料                            | **有料**                           | 公開後に無料アプリを有料へ変更できない。内部テスト中のテスターは有料アプリでも無料でインストールできる     |
| デベロッパー プログラム ポリシーの確認 | 内容を確認してからチェック               | アカウント保有者が内容を読み、遵守できることを確認して操作する                                             |
| 米国輸出法の確認                       | 文面を読み、確認欄にチェック             | 米国輸出法の対象となる可能性があることの確認。チェックだけで輸出規制への適合や免除が認定されるわけではない |

アプリ名・言語・アプリ/ゲームの区分は作成後に変更できる。パッケージ名は一度 Play に登録すると変更できないため、AAB と同じ値を使う。有料を選んだ場合、製品版で価格を設定すると利用者に購入が必要になる。価格設定と販売する国・地域は Play Console で確認する。

### Play App Signing

初回の AAB アップロード時に Play App Signing に登録し、特別な鍵を持ち込む理由がなければ Google が生成するアプリ署名鍵を使う。アプリ署名鍵は Google が配布用 APK に署名する鍵で、アップロード鍵とは別物。

このプロジェクトの `release.jks` は AAB を署名して Console にアップロードするための**アップロード鍵**。AAB のアップロード時に既存のアップロード鍵として登録し、アプリ署名鍵としてアップロードしない。`release.jks` と `keystore.properties` は安全に保管し、Play Console にファイルとしてアップロードしたり、他人に共有したりしない。アップロード鍵を紛失した場合は、Play Console からリセットを申請できるが、鍵とパスワードのバックアップは別の安全な場所に保管する。

### 米国輸出法と暗号化

米国輸出法の確認は、開発者の所在地にかかわらずアプリが米国輸出法の対象となる可能性を認識するためのもの。アプリが暗号機能を使う場合、確認欄へのチェックだけで法令適合性や輸出許可・免除が判定されるわけではない。具体的な法的分類や追加手続きが必要かは、この欄だけでは判断できないため、必要に応じて輸出管理の専門家に確認する。

SanpoGuide は HTTPS 通信、端末内の API キー暗号化保存、第三者チャンネル署名の Ed25519 検証を使う。Play Console で暗号化の利用について別途質問された場合は、これらの実装も踏まえて正確に回答し、実装を変更したら回答を見直す。

### 内部テスト用リリース

1. リリース用 AAB を作る。プロジェクトのルートで実行する。

   ```powershell
   .\gradlew.bat :app:bundleRelease
   ```

   出力先: [`app/build/outputs/bundle/release/app-release.aab`](../app/build/outputs/bundle/release/app-release.aab)。既に作成した AAB を使う場合も、アップロード前にこのパスのファイルがあることを確認する。
2. Play Console でアプリを開き、**[テストとリリース] > [テスト] > [内部テスト]** を開く。
3. **[新しいリリースを作成]** を選び、**[App Bundle]** の欄から上記 AAB を選択してアップロードする。Play App Signing の案内が表示されたら、Google が生成するアプリ署名鍵を選んで登録を完了する。`release.jks` や `keystore.properties` はアップロードせず、誰にも共有しない。
4. リリースの詳細に次の値を入力する。

   | 項目 | 入力例 | 説明 |
   |---|---|---|
   | リリース名 | `内部テスト 1.1.0 (2)` | Play Console 内でリリースを識別する名前。利用者向けのストア表示名ではない |
   | リリースノート | `初回の内部テスト版です。アプリの動作確認にご協力ください。` | テスター向けの変更内容。言語を選べる場合は日本語を指定 |

   これは今回の初回内部テスト向けの例。後の更新では、テスト対象の変更点に合わせてリリース名とノートを編集する。
5. **[次へ]** または **[保存]** を選び、Console の検証結果を確認する。警告やエラーが出たら内容を読み、解消が必要な問題を直してから進む。
6. 検証に通ったら、画面の案内に従って **[内部テストに公開]**（または同等のロールアウト操作）を実行する。初回の反映には時間がかかることがある。
7. 内部テストの **[テスター]** タブでメールアドレスのリストを作成し、Play ストアで使う自分の Google アカウントを追加して保存する。メールアドレスはこの文書に書かない。
8. Console に表示される参加リンクをその Google アカウントで開いてオプトインし、Android 端末の Play ストアからアプリをインストールする。

内部テストは最大 100 人までで、自分一人で利用できる。**12 人以上が 14 日間参加する要件は内部テストにはない**。この要件は、対象となる新しい個人アカウントで製品版へのアクセスを申請する前のクローズドテストに適用される。

## データ セーフティ

Google の定義では、端末から外に送るものは、送り先が運営者のサーバーでなくても「収集」になる。散策ガイドは運営者のサーバーを持たないが、外部サービスに送る位置などを「収集」として申告する。

| 質問                                     | 答え                                                                                                                                             |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 必須のデータを収集・共有するか           | はい                                                                                                                                             |
| 送るデータはすべて転送時に暗号化されるか | はい（通信はすべて HTTPS）                                                                                                                       |
| データの削除をリクエストできるか         | 運営者はデータを保管しないので、アプリの中で消せる（記録の画面・アプリの削除）。「ユーザーがデータの削除をリクエストできる手段を提供する」ははい |

### 収集するデータ

| データの種類                                                                          | 収集 | 共有   | 一時的な処理 | 任意か                           | 目的         |
| ------------------------------------------------------------------------------------- | ---- | ------ | ------------ | -------------------------------- | ------------ |
| 位置情報 > おおよその位置情報                                                         | はい | いいえ | はい         | 必須                             | アプリの機能 |
| 位置情報 > 正確な位置情報                                                             | はい | いいえ | はい         | 必須                             | アプリの機能 |
| アプリのアクティビティ > その他のユーザー作成コンテンツ（散策の状況のまとめを AI へ） | はい | いいえ | はい         | 任意（API キーを入れたときだけ） | アプリの機能 |

- **共有はいいえ**: Overpass・OSRM・Open-Meteo・AI サービスなどへの送信は、散策者が求めた機能を提供するためのもので、送り先は位置を別の目的に使う相手として渡していない。AI サービスへは散策者自身の API キーで、散策者が選んだサービスに送る
- **一時的な処理**: 運営者はどれも保管しない。各サービスでの扱いは、それぞれのポリシーに従う（プライバシーポリシーの「外部サービスへの送信」）
- **申告しないもの**: 散歩の記録・設定・API キーは端末の外に出ない（バックアップ・端末間の移行もしない）。個人情報（名前・メールアドレス）、端末の ID、アプリの診断情報は扱わない

## フォアグラウンドサービスの申告

### Android 側の権限設定

このアプリでは、[AndroidManifest.xml](../app/src/main/AndroidManifest.xml) に以下を宣言済み。

- `ACCESS_FINE_LOCATION` と `ACCESS_COARSE_LOCATION`: 散策に使う位置情報の実行時権限。アプリ起動時に要求し、散策中も位置情報を使うことを散策者に許可してもらう。経路記録とスポット接近案内の精度を保つには、端末の許可画面で「正確な位置情報」を選んでもらう。
- `FOREGROUND_SERVICE` と `FOREGROUND_SERVICE_LOCATION`: Foreground Service と位置情報タイプの宣言。
- `.walk.WalkService` の `android:foregroundServiceType="location"`: このサービスが位置情報を使うことの宣言。

`ACCESS_BACKGROUND_LOCATION` は追加しない。散策者がアプリを表示して「散策をはじめる」を押した後に位置追跡を開始するため、「常に許可」は求めない。Android 13 以降で通知権限を求められた場合は、散策中の継続通知を見られるよう許可する。

| 項目                             | 答え                                                                                                                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 種類                             | 位置情報（`foregroundServiceType="location"`、`FOREGROUND_SERVICE_LOCATION`）                                                                                                                            |
| バックグラウンドの位置情報の権限 | 求めない（`ACCESS_BACKGROUND_LOCATION` なし。散策者が画面で「散策をはじめる」を押したときに始める）                                                                                                        |
| 説明                             | 散策者が「散策をはじめる」を押してから「散策を終える」を押すまで、画面を閉じても現在地を追い、近づいたスポットの解説と、歩いた距離・経路の記録をする。散策中は通知を出し続け、通知の「終了」からも終えられる |
| 散策者への影響                   | 位置を追うのをやめると、画面を閉じている間のスポットの案内と、散歩の記録が途切れる                                                                                                                           |
| 動画                             | 「散策をはじめる」→ 通知が出る → 画面を閉じる → スポットに近づくと案内が出る → 「散策を終える」の流れを撮り、YouTube（限定公開）の URL を入れる。撮影手順は[動画撮影台本](#フォアグラウンドサービスの申告動画)を参照 |

### Play Console への入力内容

Play Console の **[モニタリングと改善] > [アプリのコンテンツ] > [フォアグラウンド サービス]** で、アプリが実際に使用する種類を申告する。Manifest の宣言とは別に、Play Console 側での申告も必要。

| 項目 | 入力内容 |
|---|---|
| Foreground Service type | **Location（位置情報）**。アプリは `foregroundServiceType="location"` を使用 |
| 具体的なユースケース | ユーザーが散策開始を明示した後の、散策中の位置追跡・散歩記録・スポット接近案内。候補に適切な項目がなければ「その他」等を選び、この用途を記述する。「位置情報の共有」や「ナビゲーション」と誤認される選択肢は、実際にその機能を提供しないため選ばない |
| 機能の説明 | 下の「機能の説明」の文を使用 |
| ユーザーへの影響 | 下の「遅延・中断時の影響」の文を使用 |
| 動画 | 下の手順で撮影し、確認できる YouTube の限定公開 URL を入力 |

**機能の説明**

> 散策者がアプリ画面の「散策をはじめる」を押すと、散策を終えるまで位置情報を継続して取得します。画面を閉じている間も歩いた距離・経路を記録し、近くのスポットを検知して解説や通知を表示するために使用します。散策中は継続中であることが分かる通知を表示し、散策者はアプリまたは通知から散策を終了できます。位置情報を他のユーザーと共有する機能はありません。

**遅延・中断時の影響**

> この処理は散策者が「散策をはじめる」を押したときに開始し、予約・延期して実行する処理ではありません。位置情報の取得が中断すると、中断中の距離・経路が記録されず、画面を閉じている間にスポットへ近づいても案内を受け取れないことがあります。散策者はアプリを開いて状態を確認するか、散策を終了して再度開始できます。

### フォアグラウンドサービスの申告動画

Play Console の審査担当者が、散策者による開始操作と、画面を閉じた後も位置追跡が続くことを確認できる動画を用意する。実機で撮影する場合は、位置情報と通知の権限を許可し、個人情報や実際の自宅位置が映らないテスト場所を使う。エミュレーターを使う場合は、模擬位置を移動させてスポット接近時の動作を再現する。

撮影前に、審査対象と同じリリース版を端末にインストールし、位置情報の権限と通知を許可して、位置情報が取得できることを確認する。位置情報の権限はアプリ起動時に求められるため、散策開始前に許可しておく。動画は編集で操作の流れを誤解させず、次の場面を一続きで見せる。

1. アプリのメイン画面を表示し、「散策をはじめる」ボタンを見せる。
2. 「散策をはじめる」をタップして散策を開始する。
3. 散策中の通知が表示され、終了操作が用意されていることを見せる。
4. ホーム画面に戻るか画面を消し、アプリを前面に出していない状態で通知が残っていることを見せる。
5. 実際に移動するかエミュレーターの模擬位置を動かし、位置追跡が続くこととスポット接近時の案内を見せる。
6. アプリに戻って散策中の表示を見せ、「散策を終える」をタップする。通知が消え、追跡が終了したことを見せる。

撮影した動画を YouTube に**限定公開**でアップロードし、別のブラウザーまたはログアウト状態でも再生できる URL であることを確認してから Console に貼り付ける。限定公開の URL はリンクを知る人が閲覧できるため、動画に個人情報や自宅の位置を含めない。
