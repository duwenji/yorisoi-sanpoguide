# 散策開始前のプラン入力・立ち寄り提案 設計

## 背景

SanpoGuide は、散策開始後に位置情報を追跡し、周辺スポットへの接近や状況に応じて話しかける。メイン画面には散策開始ボタン、周辺スポット一覧・地図、スポットへの徒歩経路表示があり、散歩の記録は端末内に保存される。現状、散策者がその日の目的や予定を開始前に伝える手段はない。

`docs/TODO.md` には、時間・距離・テーマから周回ルートを提案する案が記載されている。本設計では、散策開始時に希望を入力できるようにし、周辺の立ち寄り候補と散策中の案内を合わせる。道路に沿った完全なルート生成は初期版の範囲外とする。

## 目的

- 散策者が歩きたいテーマや時間・距離、予定を散策開始前に任意で伝えられる。
- 周辺スポットから立ち寄り候補を提示し、散策者が選んだ場所を散策中の案内で優先できる。
- 選択した希望を会話に反映し、散策者が望む雰囲気に近づける。
- 入力を必須にせず、プランを作らない場合は現在の散策開始体験を維持する。
- 予定した場所や自由記述をAIサービスへ送らず、プライバシーと既存のデータ最小化方針を保つ。

## 対象範囲

### 初期版に含める

- 「散策をはじめる」操作から開く、任意入力のプラン画面。
- テーマ、歩ける時間・距離、周辺スポットの立ち寄り候補選択、任意の自由記述メモ。
- 周辺スポットを使った候補 3 件までの提示と、候補の選択・解除。地図上・一覧上からのスポット追加も可能にする。
- 選んだスポットを端末内で保持し、散策中に通常の接近案内より優先すること。
- 選択式のテーマ・時間・距離の要約を、会話生成に必要な範囲でAIへ渡すこと。
- プランのローカル保存、既存の散歩記録削除に連動した削除、過去データとの後方互換性。
- 候補取得に失敗したときも、その理由を示したうえで散策を開始できること。

### 初期版に含めない

- 出発地・到着地・経由地を結ぶ道路上の経路最適化、周回経路や所要時間の保証。
- 新しい経路検索サービスやサーバーの追加。
- 自由記述メモ、予定地点一覧、予定地点の座標やルート座標のAI送信。
- 入力情報を使った分析・テレメトリー。
- プラン入力を必須にすること。

## 利用体験

1. 散策者がメイン画面の「散策をはじめる」を押す。
2. プラン画面で、テーマと歩ける時間・距離を選ぶ。テーマは現在選択中のチャンネルと独立して選択できる。テーマは「指定なし」または既存のスポットカテゴリから 1 つを選ぶ。時間は 30・60・90 分、距離は 1・3・5 km の選択肢を設け、それぞれ任意にする。両方入力してもよい。
3. アプリは既に取得済みの周辺スポットから、テーマが一致するスポットを優先して最大 3 件提示する。順位付けは既存の `SpotChooser` と同様、スポットの注目度にテーマ適合の加点を加え、同点なら近い順にする。テーマが未指定なら近い順にする。時間・距離は希望として会話生成に使うが、候補の合計距離・所要時間は算出しない。提案は立ち寄り先の候補とし、実際の歩道経路を示すものではない。
4. 散策者は候補を選ぶ／解除する、地図や一覧から場所を追加する、任意のメモを入力する、またはプランを飛ばしてすぐ開始する。
5. 開始後、選択したスポットは端末内で案内優先度に使う。位置と従来の近接判定に従って案内し、距離・道路事情を考慮した到着時刻は約束しない。
6. 周辺スポットを取得できない場合は候補を表示できない理由を伝え、再試行または候補なしで開始する選択肢を出す。散策開始自体は妨げない。

開始前画面には、プランなしですぐ開始する明確な操作を置く。既存の散策開始操作は、プラン画面をスキップすれば同じ結果になる。

## データとプライバシー

### 端末内データ

プランは現在の散歩セッションに属し、選択式の希望、選んだスポットの識別子・表示名・座標、自由記述メモを保持する。散歩記録にもプラン情報を含め、設定済みの保存上限と記録全削除に従う。履歴 JSON への追加フィールドは任意項目として読み込み、既存の散歩記録をそのまま読み込めるようにする。

実行中プランはアプリ専用のローカル領域に保持する。`WalkService` が Android の sticky restart で Intent なしに再生成された場合も、実行中プランを読み戻して新しい `WalkSession` に引き継ぐ。位置・距離・会話など既存セッション情報の復元範囲は広げない。正常終了時はプランを記録へ保存した後に実行中スロットを消す。

履歴画面にはテーマ・時間・距離・選んだ立ち寄り先を表示する。自由記述メモも端末内の散歩記録に残し、同じ記録詳細から確認できる。別の散歩にプランを自動で引き継がない。

### AIサービスへの送信

- 送信を許可するのは、テーマ・時間・距離など選択式の希望から作る短い要約に限る。
- 自由記述メモ、選択した全地点の一覧、プランの座標・ルート情報は送らない。
- 選択地点の接近時に通常のスポット案内を生成する通信は、現行と同じ境界を維持する。通常の案内対象となったスポット情報を使い、プラン全体を追加で送らない。
- プライバシーポリシーと README の送信情報・端末内保存の説明を実装と同時に更新する。

## 実装境界

- **UI**: `MainScreen` と `MainActivity` の開始操作にプラン画面を挟み、既存の開始操作を保つ。
- **候補提示**: `MainViewModel` が既取得のスポット情報を利用し、テーマ適合を優先カテゴリとして最大 3 件を組み立てる。テーマの一致は既存のスポットカテゴリ（`Poi.category`）を使う。初期版で新規の外部経路 API は追加しない。時間・距離は候補経路の推定には使わない。
- **サービス開始**: 選択したプランを `WalkService` に明示的に渡し、サービス起動時に `WalkSession` が保持する。何も入力されていない場合は空のプランとして扱う。
- **案内・会話**: 立ち寄り優先情報は端末内の `WalkSession` に保持する。`WalkService` から `Narration` を経由して `WalkCompanion` へ渡す会話コンテキストには、必要な選択式要約だけを追加し、自由記述と計画地点一覧をプロンプトに含めない。
- **記録**: `WalkSession.toRecord()` と `WalkRecord` にプランの記録形式を追加し、`WalkJson` は任意フィールドとして読み書きする。既存履歴との互換性を保つ。
- **文書**: README、プライバシーポリシー、`docs/TODO.md` を実装後の振る舞いに合わせる。

## エラーと境界条件

- 周辺スポットが空、未取得、または取得失敗の場合、理由を明示し、候補なしで開始できる。
- テーマや時間・距離が未選択でも開始できる。両方入力された場合は、会話生成に両方の希望を渡す。
- 選択したスポットがセッション開始後に候補リストから消えても、保存済みプランを失わず、現在の周辺情報に基づいて案内可能な対象だけを使う。
- `WalkService` が sticky restart で Intent なしに再生成されても、実行中プランを新しいセッションへ引き継ぐ。既存の歩行経路・会話履歴などの復元は対象外。
- 履歴にプラン欄がない古い JSON は、プランなしの記録として読み込む。
- 記録の保存・読み込みに失敗した場合は、既存の履歴処理のエラー通知・ログ方針を維持し、保存成功として扱わない。

## 検証方針

- プラン画面をスキップした場合、現在と同じ散策開始・位置追跡・開始時の挨拶になる。
- テーマ・時間・距離の要約が会話生成に反映される。
- 選択した立ち寄り先は端末内で優先対象になるが、未選択のスポット案内・安全案内など既存の判断を妨げない。
- 自由記述、予定地点一覧、予定地点と歩行経路の座標がAIリクエストに入らない。
- 周辺情報の欠落・取得エラー時に理由が表示され、候補がなくても散策を開始できる。
- プランなしの既存履歴とプランありの新しい履歴が読み書きでき、履歴全削除でプランも削除される。
- プランを指定した開始操作がサービス再生成・画面回転などのライフサイクル条件で失われない。

## 初期版の成功条件

- プランの入力・提案・選択が任意で、利用者がプランの有無にかかわらず散策を開始できる。
- 立ち寄り候補と会話のテーマが散策者の選択に沿い、ルート案内として誤認させない。
- AIへの送信境界が自動テストで検証され、予定地点一覧・座標・自由記述が送られない。
- 候補取得や履歴互換性の失敗が散策開始を妨げない。
- 新たな利用者データ収集や外部サービス依存を追加しない。
